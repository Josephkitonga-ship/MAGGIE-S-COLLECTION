# Maggie's Collection

The public storefront at **maggiescollection.co.ke**: one store, one catalogue, one WhatsApp line.
Built by Flynn Technologies.

Staff tools live in a separate repository, **MAGGIES-ADMIN** (`admin.maggiescollection.co.ke`, with a
`/counter` dashboard for the shop and a `/manager` dashboard for the owner). Both sites use the same Supabase project.

## What this update changes

## "Sold out" on the shop window

The counter and manager count stock in the admin. The shop reads a public view, `product_availability`,
which says only whether each size is **in stock**, never how many are left.

- A product that has not been counted yet is never shown as sold out. It sells exactly as before.
- A sold-out size is greyed out and cannot be chosen. A product with every size sold out shows a **Sold out** badge,
  and its buttons are disabled.
- If the view does not exist yet, the shop simply shows everything as available. Nothing breaks.

## Roll-out, step by step

1. **Phase 1.** Supabase SQL editor: run `docs/supabase-counter-manager.sql`.
2. **Phase 2.** Deploy MAGGIES-ADMIN. Sign in at `/counter` and `/manager` and test with a hidden product.
3. **Phase 3.** Run `docs/supabase-merge-stores.sql`, then upload this repository.
4. **Phase 4.** Later, run `docs/supabase-single-store-cleanup.sql`.

## Departments and types

Products are filed in two levels, set by staff in the admin: **Department** (Women, Men, Kids & teens, Unisex, Shoes,
Bags, Accessories, Home & Living) and **Type** inside it. The lists live in `SHOP.departments` in `js/config.js`;
the admin repository has its own copy, so change both. Never change the store `slug` (`maggies`).

## Orders and security
- Customers never insert orders directly. `place_checkout()` reads every price from the products table,
  so nobody can post a fake price.
- A WhatsApp message and a saved order are both created for each request. Staff verify the order in the admin, and
  verifying takes the pieces out of stock.
